# D1 原生身份清单与差分格式

一个进程执行一次完整的原生 SC Closure 查询。给常规 Deagle 命令增加 `--d1-manifest NEW_FILE` 即可记录。输出路径必须尚未存在。读取器要求清单有版本头、配置、一次实际 SAT 适配器入口以及成功或发现反例的结束码。所有编号的作用域限于产生它的文件或程序对。

## 原生记录

文件以 UTF-8 TSV 存储。字段中的百分号和控制字符使用两位十六进制百分号编码。结构字段用 UTF-8 字节长度前缀拼接。首行为 `DEAGLE-D1<TAB>1`，末行为 `END<TAB>exit_code`。本地文字采用 MiniSat 的 `2*var+sign`，`-1` 为真，`-2` 为假。这两个数与 Closure 内部的特殊文字共享表示，须按字段语义解释。变量零保留。

| 标签 | 字段及产生位置 |
|---|---|
| K | SC Closure 规则修订、指针和整数宽度、端序、展开、展开断言、目标架构与布局、完整已解析选项 |
| S | 本地静态点、语义签名、唯一性、函数、诊断文件及行号。签名取实际 GOTO 函数及指令操作，同一函数中重复的操作还比较前后邻接操作 |
| X | 动态上下文、本地静态点、线程出生的动态上下文、调用者上下文，随后为每层循环的静态回边与实际展开计数。根为 0，未解析为 -1 |
| E / V | 原生图端点名或 SSA 名、动态上下文、操作角色、原始访问对象、标量类型、存储类别。合成初始写用 -2，须能证明全局静态对象 |
| A / F | A 将 SSA 符号、类型及位序连接到实际位映射中的文字。F 将 RF 选择符号连接到一对实际事件 |
| G | 当前编码器创建的门算子、有符号输出、按编码器顺序记录的有符号输入；ITE 为条件、真分支、假分支 |
| C | B、Q 或 U 来源，以及根传播、排序、去重和子句分配前实际进入 MiniSat 的全部文字。隐式序号从 1 起，跨来源连续。适配器直接消去的真常量子句没有进入该接口 |
| TERM / VALUE_DEF / H | 类型化表达式 DAG，当前 SSA 写值定义及真实写入的 guard 定义。TERM 含本地 ID、操作、标量类型、符号名或常量值、子项 ID |
| NODE | 图节点号、原生名称、原生地址组、实际读写标志、实际并查集父节点 |
| MEMBER / IN / OUT | 代表节点的完整成员集合；每个节点实际保存的入向和出向块内次序 |
| EDGE | 关系种类、有向端点、本地声明文字、原生文字表反查的两个端点、原生端点对表反查的文字 |
| GUARD / CO | 前者是写入事件与本地 guard 文字。后者是搜索期间原生 CO 对的两节点、两个方向的文字及两个 guard |
| QUERY / TARGET / N | 选取性质目标的边界、实际选中的性质 ID、实际适配器入口的变量上界及有符号 assumptions |

B 和 Q 来自实际转换调用栈。程序约束和内存模型的编码进入 B，断言、目标使能以及本次 solve 的延迟转换进入 Q。未识别的来源归 U。动态 CO 单独登记。清单记录原生数据，不分配 SAT 变量，也不调用额外一次布尔转换。

## 对应与基础前提

静态点或动态定义碰撞、缺失出生或调用上下文、不可解释的对象均保留原因。事件键包含稳定 GOTO 点、出生和调用路径、循环实例、操作角色及访问槽。guard 表达式、写入 RHS、候选域、原子块分别登记。行号仅用于核查。运行内的 SSA 名和图节点号用于连接同一次运行中的真实表。

普通变量通过稳定定义、类型和位序建立候选。RF 与 guard 增加实际语义别名。对同一本地变量检查**全部**有符号别名、反向唯一性及两个版本中的常量折叠。选择一个参考极性后比较整个集合。没有具名锚点的门按依赖层匹配，要求算子和全部已配对输入相同，而且两边各有唯一输出。只对可交换算子排序。匹配采用完整内容比较，哈希仅作为查找索引。每个旧变量最多映到一个新变量，取反与映射可交换。

地址证明当前支持直接命名的全局静态标量。局部对象、复合对象的布局和指针解释保留为未知。块证书验证原生代表成员和并查集分区一致、全部成员可识别、双向报告的内部次序互为转置。证书保存完整成员、方向和原生 APO 连续性。完整 RF 域按某一读的所有已声明候选建立。完整竞争写域还核对同一原生地址组及写入的静态存储解释。RF 绑定要求原生文字表和端点对表双向一致。guard 绑定要求事件、实际文字和类型化定义均可解释。表达式比较在共享读处保留值身份，对确定的 SSA 写值定义递归比较，遇到不支持的操作或多义定义即停止。

## 程序对证据

| 文件 | 读取方法 |
|---|---|
| P0/P1.anchors.gz、aliases.jsonl.gz | 两侧每个具名变量的完整别名类、极性、角色和拒绝原因；JSONL 另列每个语义别名实际出现的全部本地文字 |
| variables.tsv.gz | 侧别 0/1、本地变量、对端有符号文字或 -1、角色、理由、别名类 ID。门的结构见原生 G 行 |
| occurrences.tsv.gz | 侧别、原生 C 序号、来源、基础子句键或 0、拒绝理由。可定位首个未映射的精确文字 |
| clause-keys.tsv.gz | 键、来源、排序去重后的语义文字。非恒定文字使用 P0 命名空间，0/1 表假/真。保持出现记录、来源、重复次数和逻辑内容之间的区分 |
| clause-counts.tsv.gz | 键、来源、P0 出现次数、P1 出现次数。查询作用域要求两边有同一组已选目标和完全映射的 assumptions |
| declarations.jsonl.gz | 每行依次为侧别、类别、本地对象、语义槽、声明键、状态、原因。常量与变量之间的 guard 变化可确证撤销与新增，其中尚未映射的新文字仍无可用键 |
| semantic-keys.jsonl.gz | 每个整数键及其完整规范内容。嵌套结构引用更早建立的整数键 |
| summary.json、independent-check.json | 分侧分类和计数、未知原因、实例、分析用时，以及对全部原始出现的独立复核 |

`matched` 表示两边均实际登记了相同前提。`retired` 和 `added` 表示对应版本已识别的前提在另一侧缺少同一规范内容；这也可能源于动态上下文键变化。`unknown` 缺少足够证据。键为 0 或状态为 unknown 的项均不能支持保留旧证明。查询专用叶只在原查询作用域内可用。当前差分只登记基础叶，尚不计算学习子句的有效性。

## 复算

从开发树根目录执行，下列变量指向新的输出目录或已解压的两个清单。

```bash
g++ -std=c++11 -O2 -Wall -Wextra -pedantic dependency-reuse/d1/boolean_diff.cpp -o "$engine"
python3 dependency-reuse/scripts/diff_d1.py "$old_manifest" "$new_manifest" "$engine" "$pair_output"
python3 dependency-reuse/tests/d1/check.py "$deagle" "$engine" "$fib_P0_manifest" "$test_output"
```

正式运行使用 `scripts/run_d1.py` 复用 D0 冻结输入的运行器。审计构建使用 `scripts/build_d1_audit.py TREE BUILD_LOG NEW_DIRECTORY`，以各自构建日志中的原编译、链接参数重编两份观察对象。独立核对与归档入口为 `scripts/package_d1.py RECORD OFF PROBE_STOCK PROBE_DEV DELTA TESTS NEW_EVIDENCE --active-probe ACTIVE_PROBE`。
