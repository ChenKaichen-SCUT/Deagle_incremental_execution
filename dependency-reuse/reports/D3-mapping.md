# D3 身份映射专项

三个冻结程序中，circular-buffer 的跨版本永久 Boolean 输入匹配数从 79,087 增至 126,081。D2 永久纯 Boolean 证明实际用到的匹配输入增加了 111 个，完整旧证明仍保留 12 条。airline 的 7,906 个自比未知输入中，有 427 个现在能在 P0 自身取得身份，跨版本保留数仍为零。

本专项从同一份 D2 原生证明归档出发，更换输入映射后重新计算失效，从而测量映射改动本身的影响。下文的学习 ProofId 均属 D2。D3 新记录的理论理由、严格混合 CDCL 证明及其联合失效结果见[阶段主报告](D3.md)。

## 身份证据

1. 原生 `--d3-layouts` 配合 `--d1-manifest`，在 V 定义记录和 A 编码位记录旁附加聚合布局。类型签名包含目标 ABI、端序、对齐、按原序排列的组成部分、位宽和全部可达类型标签定义。调试源位置中的工作目录随运行改变，故从签名中剔除。跨版本比对完整签名，并检查定义身份、作用域、位序、实际编码宽度以及双向别名唯一性。
2. 聚合对象可能包含指针或填充。本轮只给小端目标下各重叠视图都可认证的整数前缀分配身份。结构体检查首个字段，联合取各视图可认证前缀的交集，整数数组核对元素宽度和固定长度。circular 与 airline 的 `pthread_mutex_t` 均展开为 320 位，P0 和 P1 都仅认证低 32 位。额外的位、缺少动态定义或别名证书的位继续记为未知。
3. 编码器门比较算子、每个已对应的输入及其极性、输出极性。可交换运算规范化输入次序，ITE 保留三个操作数的位置。若多个输出实现同一函数，再以永久 Boolean 子句中的使用位置消歧。这些位置必须具有可翻译的其他文字，且签名在两侧均唯一。通过后才继续向下游门传播对应。所有对应均为部分、有符号、单射映射。整个流程不使用逐变量 SAT 等价测试。

独立检查逐个复核两侧原始输入的作用域、完整带符号内容、匹配计数及变量逆映射，并核对三个病例的 **7,253、27,190、7,603** 个已匹配门的实际编码函数。小型测试覆盖重编号、反相、相同使用位置的重复门、仅出现在查询中的使用位置、等宽异型及整数位边界。[检查程序](../tests/d3/mapping_checks.py)

### airline 的 7,906 个输入

这些输入均是 D2 永久纯 Boolean 证明实际使用过的叶。改进后 **427 个自比已对应、跨版本仍未知，7,479 个自比仍未知**。原有 5 个可跨版本匹配的输入继续匹配。冻结修复确实改变了锁操作；在这批使用输入中，当前证据仍不能把任何未知子句认定为“已完整翻译、整条内容消失”。

- 学习 `997583` 的第 231 次输入使用文字 1550，即 `bookings#9` 的第 0 位。该位现在具有可核对的整数布局，自比成功。跨版本检查返回 `peer_alias_absent`，对应的完整值定义别名未出现。
- 学习 `928263` 的第 20,888 次输入使用文字 7350、42501。两个门分别受阻于操作数 6711、6708。6708 是 Guard，实际绑定仍报告 `unsupported_object_or_type`。给静态聚合值位增加布局证据无法单独补齐这个理论端点。

## 成本

两种身份记录模式在同一正式 ELF、同一冻结配置上交替运行。每格为单次冷进程观测，固定 CPU 0，未清空操作系统缓存。前列开启 D1 身份记录，后列同时开启聚合布局记录。下表覆盖 3 对输入、2 个版本、2 种模式的全部 12 次运行。单次墙钟波动不能作为加速结论。

| fib P1 | 2.0562 → 2.0673 | 29,440 → 29,440 | 0 |

## 复验

使用主报告所列的固定源码与工具。在 Linux 上把下列三个工具变量设为绝对路径，并选取尚不存在的输出目录。驱动程序重新获取两种原生清单、运行基线差分、改进差分和 P0 自比，用原始 D2 归档检验同一批学习证明，再复核两侧子句清单和门函数。

~~~sh
python3 dependency-reuse/tests/d3/mapping_checks.py "$D3_DIFF"
python3 dependency-reuse/scripts/d3_mapping.py "$D3_BINARY" "$D3_DIFF" "$D2_CHECK" "$NEW_OUTPUT"
~~~

正式运行的原生 ELF SHA-256 为 `5f863d39f09c173428185de3f93a5c0efdfc3eaf088f84403c21830c0b9d707e`，差分器为 `75542b82b5aa80d9d362f62b1889db5887d2a44e1de991bdbfbbbd10f67b664c`，D2 归档检查器为 `580b766f40e88605f8fd8ea3b1b51ae6542ef5f565adf0c2add3e3767318adb7`。
