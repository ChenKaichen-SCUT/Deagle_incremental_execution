# D4.2 在线 Light 记录

Audit 保存原始子句、消解主元、逐步结论、理论推导和实际 SAT 理由。Light 在同一原生输入、根传播、冲突分析、成功最小化和理论放电入口采集直接父支持。持久化记录包含共享父 ID、理论声明、不可认证的来源、完整出生文字与作用域。每个输入在提交时获得 occurrence ID。Light 用原始模型中的那一行作为输入内容，在加入求解器前短暂保存当前原子句，以便缩短发生时立即捕获被消去的根赋值支持。[在线记录器](../../minisat-2.2.1/minisat/core/SupportStore.h) · [原生记录入口](../../minisat-2.2.1/minisat/core/ProofStore.cc)

理论中间结论保留带条件的临时句柄。与 D4.1 相同的原生规则及端点检查先执行，条件取反后的文字集合必须与送入 SAT 的实际理由一致。已检查的条件集合可复用。跨过该边界时才物化必要的共享支持片段，直接写入有界缓冲的归档。发生冲突分析时继续传递此前出生的稳定 ID。搜索数据库的 CRef 迁移由已有 GC 回调维护，持久 ID 独立于 Clause 的释放。

搜索迭代之间的安全点回收未引用的临时对象。根集合包括静态声明、已安装的边、RF 与 Guard、待处理的三元组、排队的理论赋值及冲突。未物化的临时父链必须一起保留。已物化父链可从内存退役，归档中的直接父 ID 仍可从所有后代访问。句柄单调分配，旧代以排序表查找，无法把退役句柄解释为别的分支。只在精确匹配父序列和规则时命中有界缓存。条件索引、常驻 SAT 引用、出生历史和经过认证的条件集合仍占用内存。[回收及悬挂引用夹具](../tests/d42/lifetime.cpp)

离线检查器按实际出生顺序对两个 DAG 的标记、完整有符号结论、Boolean 输入 occurrence 和理论声明进行比较。它对规范化的父表达式做共享编号，折叠单父结点、重复父及父顺序。哈希碰撞时比较完整键。规范表达式相同蕴含全部基础支持相同。另一个独立程序从 Audit 归档、观察器的出生/理由流和 P1 重新构造的输入成员表重放每次真实推导。P0 的最小化后 LBD 以不同决策层计数，出现根层时计一次。历史访问计实际 watcher 传播、冲突和 UIP 访问，驻留状态由结束时的子句与根单位快照确定。[共享支持检查](../d4/support_check.cpp) · [独立证明与语义检查](../scripts/audit_d42.py)
