## 比较口径

每轮按冻结顺序运行 fib_updates_8、circular-buffer、airline_reservations_6、fib-snapshot-11。六种模式占用原预注册的相应位置，原 Light 位置按奇数轮质量开启在前、偶数轮关闭在前拆成两项。每个原生求解使用独立进程与目录，同一病例同一轮在遇到第一个 Compact 模式时生成唯一 P0 库。每个 Compact 臂独立完成 P1 建模与准备，计算周期时均计入同一个实测 P0 完整墙钟一次。[预注册](../configs/d43-plan.json) · [开跑前锁定的执行细则](../configs/d43e-execution.json) · [实际顺序与串行检查](evidence/d43e/schedule-check.json)

三轮共 108 个主实验原生进程，全部在 WSL2 的 CPU 0 串行执行。准备子进程、P0 封存与父运行器也固定在 CPU 0。使用自然页缓存及原定资源限额。三例修复与历史对照均保留原有输入、性质、线程规模、SC、ABI 和展开界。统计分母包括首轮及 airline 的全部零候选验证。修复已冻结，计时边界为两次独立版本验证及部署必需的记录、封存、准备、导入。计时后单独执行正确性复核。[构建、输入与环境回执](evidence/d43e/build-isolation.json) · [原始数据说明](evidence/d43e/archive.json)

Light-quality、Light-no-quality、Compact 和同编码 off 均使用 D 审查过的同一生产 ELF。off 也输出相同编码的模型清单。Light 两臂使用同一 D4.2 Light 记录路径，分别保留或关闭出生历史质量统计，均计入模型清单、完整序列化、载荷摘要与封存。它们的测量终点为 P0。Compact 的 P1 包含配置回执设置、完整原生进程及其准备子进程。stock 的完整墙钟、RSS、性质和求解计数来自真正未修改的 D0 ELF。原版缺少的搜索、重启和首次根边界时钟，沿用 D 的独立计时构建，主矩阵完成后另作 24 次串行观测，逐病例逐轮核对搜索轨迹。stock 的墙钟收益直接使用原版实测值。[运行器](../scripts/run_d43e.py) · [进程时间、时钟来源及 RSS](evidence/d43e/runs.tsv)

## 复算与原始证据

在仓库根目录用标准 Python 从已发布的逐轮数据重算全部记录和净收益门槛。该检查单独使用有理数计算比例，核对每一轮的绝对差、记录成本降幅、确认条件以及原使用计数。

```sh
s=dependency-reuse/scripts
e=dependency-reuse/reports/evidence
python3 "$s/recompute_d43e.py" "$e/d43e"
```

从原生输出复算可使用以下命令。E 的原始归档含全部正式运行、单独的 stock 时钟运行、完整的进程回执、模型、库、准备产物、原生使用回执、启动顺序和日志。D 归档提供本轮同映射的已认证精确对照。完整恢复并校验了 1,861 个文件，共 4,210,169,949 个原始字节。再次从原生回执生成的 13 份汇总和独立算术复核结果均逐字节相同。[归档清单](evidence/d43e/archive.json) · [独立算术复核](evidence/d43e/rational.json) · [文件摘要](evidence/d43e/files.json)

```sh
set -eu
s=dependency-reuse/scripts
e=dependency-reuse/reports/evidence
T=$(mktemp -d)
python3 "$s/d43b_archive.py" verify "$e/d43e/raw"
python3 "$s/d43b_archive.py" restore "$e/d43e/raw" "$T/E"
python3 "$s/d43b_archive.py" restore "$e/d43d/raw" "$T/D"
python3 "$s/summarize_d43e.py" "$T/E/formal" "$T/D" "$T/review"
python3 "$s/recompute_d43e.py" "$T/review" > "$T/rational.json"
cmp "$T/rational.json" "$e/d43e/rational.json"
```

重新执行原生计时使用 `run_d43e.py D_NATIVE D_TOOLS STOCK_OBSERVER NEW_DIRECTORY`。D 归档恢复后的三个参数依次是 `native/production`、`tools` 和 `stock-clock/deagle_exe`。恢复可执行权限后，运行器会校验生产 ELF、全部准备工具和时钟观察器。真正的 stock 读取自 `configs/build.json` 中绑定 SHA-256 的 `binary_path`。运行器使用新的结果目录并自动按初始三轮判定确认轮次。[正式计时源码](../scripts/run_d43e.py)
