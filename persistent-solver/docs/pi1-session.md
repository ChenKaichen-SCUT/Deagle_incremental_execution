# PI-1 会话与证据格式

`PersistentClosureSession` 拥有一台原生 `ClosureSolver`。事务通过完整模型接口进入，固定模型适配器使用第一次原生查询的归档。后端保留 MiniSAT 的变量、子句、watcher、活动度和相位。每次激活理论上下文均创建新的 `closure` 实例。构建入口为 [build-pi1.sh](../scripts/build-pi1.sh)，会话和原生理由出口分别见 [session.cpp](../src/session.cpp) 和 [EpochSession.cc](../../minisat-2.2.1/minisat/core/EpochSession.cc)。

## 边界与映射

`append_version` 先检查先前结果已保存、无活动查询、根层、配置、局部编号、出现编号、端口、Guard、原子块及完整读源域，再安装新版。任一安装期异常都会关闭该会话的后续查询能力。只读校验失败可继续使用上一版。所有公开操作按会话互斥。中断测试从下一次查询开始生效。`close` 释放求解器，保留最后的统计回执。

PI-1 的实证输入为已经审计的诊断映射。P0 只读取自己的事务。宿主收到 P0 的完整结果后才生成并发送 P1。P1 的 `BASE` 必须等于会话实际读取的上一事务 SHA-256。准备器还将两版本的原始归档和直接身份目录核对到 PI-0 锁，检查键和带符号双向单射。理论别名按实际端口的符号、角色及端点逐项复核。事件对应要求地址及读写角色保持。匹配失败分配 fresh。普通变量的认证依赖受信任的冻结映射生产者，自行制作的文件校验值只能验证传输完整性。

原生局部文字取 `2*v+sign`。常量 `-1` 表示真、`-2` 表示假。后端经同一 `newVar` 编号空间分配程序变量、不可决策的控制变量和动态 CO 方向。正常输入规约在全局文字空间完成。真常量或重言式整个跳过，假常量移除，重复文字合并。内容相同的多次出现激活同一子句 selector。同内容属于两个不同查询时各有自己的控制。空 B 安装为永久的负 selector 单位，B 单位安装为二元句。Q 额外带 `¬q`。原生查询 assumptions 保持原顺序，常量查询通过一个固定真根文字表达。

## 图代次与理由

合法图屏障包括当前正 epoch 和所有其余负 epoch。完整事件、地址、位置、端口和极性、PO/APO 有向边、块、RF/Guard/RACE、候选域以及配置构成不可变比较键。实现保留输入顺序。这会保守地区分部分内容相同、枚举顺序不同的模型。通过屏障后重建工作图并补齐 scope，从本代独立游标的起点重放 Boolean trail。根层简化使用的父类传播游标不会推进理论游标。离开屏障销毁图、所有索引、原子集、理论 trails、队列及临时冲突。屏障以上的回跳回滚两个引擎的层，并丢弃旧队列中尚未消费的传播。

六个原生传播回调保留最先入队的完整文字流。静态矛盾及顺序环也进入受保护出口。传播 CRef 的第一个文字是结论，其他文字均假，跨层冲突先恢复到最高假文字层。已真的结论直接结束，已假的结论转成冲突。临时冲突 CRef 保持到 UIP 消费或探针回退。普通理论理由存放于原生 learnt allocator。CO 方向及实际 Guard、负 epoch 一起进入扩展子句，同图按端点恢复已有两向绑定。SAT 时先复制本版带符号模型与事件序，再回退。真实反例复算使用该副本。

## 事务文件与观测

文件采用 UTF-8、制表符字段、LF 终止，每行进入 SHA-256。读取器逐行核对标头、记录总数、终止符以及完整字节摘要。紧邻文件的 `.sha256` 存放期望摘要。字节校验使用 Linux AF_ALG。表中端点均为本版目录下标。

| 记录 | 字段或含义 |
|---|---|
| PI1.1 | 本版原生变量总数、查询号、理论规则版本 |
| CONFIG | 完整冻结配置内容 |
| B / Q | 单条原始出现的有符号文字，保留输入次序，零文字行代表空子句 |
| NODE | 原生事件名、地址类、读/写/初始标志、原生输出位置 |
| EDGE / GUARD | 关系、端点和实际绑定文字，或单事件与 Guard 文字 |
| BLOCK / DOMAIN | 完整块成员，或读事件及完整候选写目录 |
| BASE / MATCH / EVENTMATCH | 上一事务摘要、旧变量到带符号新版文字与证书、已认证的端点对应 |
| TARGET / UNWIND / GOAL / ASSUME / NEWATOM | 性质、展开义务、性质目标、原生假设、后续查询的新变量 |
| END | B 与 Q 的原始出现总数 |

固定的控制向量顺序为按注册顺序的全部 epoch、全部查询、全部规范内容 selectors、当前原生 assumptions。证据文件按次拼接。每段以四个小端 uint32 开始，依次为版本号、查询号、总文字数和专用控制文字数，随后为相同数目的小端 uint32 原生带符号文字。保存正负两部分的全部实际文字。已封存的原始 occurrence 序和本格式可重建每个 selector 的内容。

小例 `REASON` 来自已分配的实际 `ca[cr]`，包括真值与层。`ENQUEUE` 读取赋值实际持有的 CRef 以及 antecedent 在 trail 中的位置。`BIRTH` 和 `USE` 记录本会话出生号与原生使用位置。GC 重定位只更新观测标签。`USE` 的类别 0–3 分别表示 watcher 传播、冲突、分析、成功的最小化。实验原始大模型保留逐类统计及完整带符号 assumptions，详细逐理由观测只用于正确性小例。

无搜索探针只产生 `BOUNDARY_FIXPOINT`、`BOUNDARY_FALSE_ASSUMPTION`、`BOUNDARY_CONFLICT` 或中断。实际处理前缀含被检查到并失败的最后一个假设，建立的帧数另计。`joint` 含图初始化和重放，`activation` 是其中的图初始化子项。`boundary` 从开始处理已建好的假设到回退结束，完整搜索模式则覆盖本次原生 solve。诊断解析、安装和构建控制向量分开记录。RSS 是进程到该版结束的历史峰值。
