# 动态证明、审核与原生接口

## 证明对象

对当前查询的完整有序布尔输入记为 (B_i)，对固定原生 Closure 的声明和规则记为 (T(D_i))。先把 P0 的原生文字转换为事件语义身份、完整别名组和极性，再在 P1 上求有符号映射。变量号和 CRef 仅用于各自查询内部交叉核对。每个求解目录同时保存完整输入、事件映射、源程序摘要和查询 assumptions。阶段 11A-T 的 T1/T2 用于身份与具名前提，T4 限于有限正向规则，T5/T6 用于条件理论结论，T7 用于学习证明的叶子与消解。本原型把未经证明的原生动态机制留在当前查询中。[阶段 11A-T 定理](../stage-11a-theory/theorems-and-proofs.md)

### P0 的实时记录

`proof.log` 是工作进程在当前搜索中写出的记录。N 把本次节点号连到 Deagle 原始事件名，`events.tsv` 再连到语义身份。E 包含原生冲突端点、外层 RF/Guard/CO 触发点及带符号子句。G 是当时已点亮的写 Guard，R 是实际存在的 RF 及其文字，I 是已执行的具名 WS/FR 规则实例。原型在原生创建 co 或 fr 边处记下两个写和一个读，按原生 push/pop 回撤观测。V 保存发生冲突的决策层、assumptions 以及每个冲突文字的当前赋值和层级。P 是反向 RF 的预防理由进入实际 Clause 分配器时的对应记录。只有原生接受入队、同一轮传播实际分配、带符号内容完全一致的理由才可作为该类叶子。记录中的静态声明来自同一查询开始前的全量快照。超预算的冲突保留 X 记录，Z 给出总数。

独立构造器利用当时的活跃前提，确定性恢复一条通往原冲突端点的有根推导。它可以为传递性选取另一条合法路径。WS/FR 的源写、读和竞争写必须在当时保存的 I 记录中出现。预防性证明允许临时假设使被推出的负 RF 文字为假，推导反向顺序与该 RF 构成的矛盾。只有完整的带条件子句才可跨查询使用。单独的预防传播子句只可充当混合证明的叶子，T 模式导入实际发生的循环冲突。

| 原生情形 | 审核所需证据和处置 |
|---|---|
| 普通顺序环 | 检查当前 PO/APO、RF 或有根 WS/FR 步骤以及连接到同一事件的末端路径。 |
| RF 激活 | 核对源写、读、实际活动的选择文字和反驳子句时的符号。 |
| WS/FR 推出次序 | 检查实际实例、前驱顺序、已选 RF、两个活动写和三者的同址关系。 |
| 原子块内或块间冲突 | 检查块的完整成员、有向 APO、具体端点以及块提升的父边。 |
| Guard 激活 | 保存外层触发，参与 WS/FR 的 Guard 必须是恒真或由该子句的反面保证。 |
| 预防性传播 | 仅实现由反向顺序排除候选 RF 的反证。未观测完整依据的其他预防、三元组或竞态理由退役。 |
| 动态 CO | 原生分配的方向变量留在本查询。方向和稳定定义未认证时停止跨版传递。另有原生双向及改号测试。 |
| 混合冲突 | 从实际 analyze 中记录原始 Boolean 子句、获证理论叶和已完成的学习证明。任一必要父节点缺失均拒绝。 |

每个证明节点保存规则、两个语义事件、父节点和必要的规则实例。独立检查器逐步验证静态声明、RF、原子块提升、顺序传递、coherence 和 from-read。它还对证明涉及的事件核对类型、地址、Guard 表达式、整个原子块及方向、同址事件全集和 RF 选择域。新增竞争写而又缺少局部失效证明时保守拒绝。

P1 另用新建的同版原生 Closure 作一次契约核对。这个进程只加载 P1 的完整理论声明，把拟导入的理论子句取反作为根单位，不加载程序 CNF 或查询 assumptions，冲突预算为零。必须实际得到 UNSAT 并且没有作出决策，才允许使用这条理论叶。该检查和独立语义步骤均须通过。归档中的每项均给出结果、决策、冲突和传播数。严格 SC 终局性质没有被扩展为原生剪枝公理。

### 1-UIP 与跨版本重证

A 记录 analyze 的两个相邻冲突分析步骤之间的实际消解文字和完整原因子句。b 指原始 Clause，t 指已登记的理论理由，l 指较早的 CDCL 学习结果，u 表示来源未核实。Q、L 分别是原生最小化前后的子句。D 保存被略去的根文字或最小化文字所用的实际赋值理由。CRef 可在当前查询中查到原生出生位置，同一位置的内容须再次相符。删除和 GC 会清理对应的观测引用。

P0 的库保存共享的证明 DAG。每个 resolve 节点包含两个父节点、指定极性的消解文字和结果子句。原始子句在提交时若因根传播缩短，须从原始输入和可证明的根单位重放。最小化展开真实 D 原因到最终子句的文字，必要时使用显式、可验证的弱化。缺失的单位理由、需要假设作为无条件叶子、来源不明的学习信息或深度超限都会中止该证明。完整 P0 混合证明至少包含一个动态理论叶、一个 Boolean 输入叶和一次真正的消解，最终子句不能等于单独的理论叶。[子句最小化论文](https://fmv.jku.at/papers/SoerenssonBiere-SAT09.pdf)

P1 先带符号重绑定最终子句。独立 RUP 生成器先尝试仅用 P1 原始子句反驳其否定，再尝试加入已通过上述双重审核的 P1 理论叶。审核器从冲突叶反向遍历单位理由，逐个重放有符号消解，并检查最后得到的子句包含于目标。每个步骤都保存消解文字、父子句索引和完整结果。越过 P1 原始子句数的叶索引由 `extra_order` 解释。仅得到纯 Boolean 证明时另行统计。通过混合审核表示在规定工作预算下得到了实际使用理论叶的证明，不声称穷尽所有纯 Boolean 证明。P0、P1 的 assumptions 均不作为无条件证明叶，因而不会把只在旧 assumptions 下成立的结论裸导入。

### 生命周期与源码位置

| 固定原生源码位置 | 11C 的处理 |
|---|---|
| Closure.cc 的 activate_edge、activate_directed_edge、light_guard、use_available_info | 跟踪实际 RF 或 Guard 的激活、具名 WS/FR 构造、冲突端点和静态块结构。 |
| Closure.cc 的 push_scope / pop_scope 与实际预防传播调用点 | 同步回撤观测记录。头文件中声明的 preventive_propagation 没有对应的独立函数体，运行路径在反向 RF 和三元组分支。 |
| ClosureSolver.cc 的 propagate、search、analyze 与 apply_literal_assignment | 在冲突进入分配器之前保存动态上下文，跟踪真正进入 analyze 的理由，记录 1-UIP、根层及最小化。P1 从实际 watcher 传播、冲突及原因访问计数。 |
| Solver.cc 的 analyzeFinal、simplify、reduceDB、removeClause、garbageCollect | assumptions 的最终冲突限定在本查询。原始子句的简化须由当前 CNF 证明。清库或 GC 清除观测引用。独立计数构建逐查询复核生命周期。 |
| ClosureSolver.cc 的 addMissingCoClauses | 运行期新建的两个方向文字和覆盖子句留在当前图。两向选择和变量换号由单独的原生控制程序测试。 |
| Solver.cc 的 addClause_ 及阶段 11B 的 epoch 切换 | P1 完整接收原始 CNF 和理论图之后，在第一次搜索之前执行审核回执。进程通过私有管道取得当前布尔输入、当前图和批准清单的 SHA-256。原生读取同一份已核验的清单字节，调用 addClause_，记录实际附着的签名和子句数。根赋值、队列、watch、原因、CO、模型及输出排名在本版重建。 |

原始数值位置可在相对 11B 生成源码的统一补丁上下文中核对。GC 后无法重新认证的旧 CRef 只会失去命中归因。根 UNSAT、输入损坏、严格 SAT 见证失败或新旧性质不一致时，候选路径停止，独立原生全量结果另存。多查询交给原工具执行全部性质。程序的非严格一般 UNSAT 只能解释为固定原生语义下的有界结论。[原生补丁](native.patch) · [构建指纹](build.sha256)
